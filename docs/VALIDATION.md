## 覆蓋情境

- UUID 與 20-byte ATT 分片相容性；UTF-8、多片、DataView offset、重複／亂序／錯誤 channel／超長／逾時。
- 連線先唯讀；協定版本不符拒絕；控制權衝突；10 秒 heartbeat；斷線後清除定時器。
- 完成正在進行的分片後優先 Stop；取消未送出的 Start／阻力；序號依實際送出順序遞增。
- 延遲的舊 GATT write 不會跨連線繼續；寫入逾時後停止使用該連線。
- 0 是有效回報；RPM／阻力各 5 秒、心率 10 秒失效；同一畫格稍晚到達的通知不會被誤判為過期。
- 以有效 RPM 完成五公里與全部三章的狀態機測試；停踩／缺值／暫停均不增加里程，速度上限及連擊規則。
- 自動阻力需要設定；支援正反向映射；幅度限制、頻率限制、命令接受與後續實際回報分開確認；超時／控制權遺失暫停。
- 實際瀏覽器中的模擬調坡、逐步調阻、停踩、暫停／恢復、斷線／手動重連、停止結算及保存。
- 人工 BLE 的控制權衝突、唯讀騎行、遙測失效停止、背景切換停止、WebGL 中斷停止；均確認 `stop`／`release` 行為。
- 無 Web Bluetooth 時仍可模擬；390×568px 畫面內保留頂部停止按鈕。
- 設定保存與清除入口；持久化內容不含卡號與心率。

五公里全程透過可重現的遊戲邏輯測試完成；瀏覽器測試驗證其實際操作流程與呈現。沒有將邏輯測試描述為十分鐘的實體騎乘。

## 尚未完成的實機驗收

以下必須使用實際 ESP32、機台與感測器完成；mock 不證明無線、電氣或機械效果。

1. 記錄 ESP32 型號、韌體 commit／SHA-256、機台型號、瀏覽器與作業系統版本。
2. 確認 BLE 配對選擇、低 MTU 分片、通知持續性及手動重連；另測 Android Chrome。
3. 確認 RPM 是飛輪或踏板來源，以舒適踩踏校正顯示比例。
4. 依設備已驗證數值填入輕／平路／重阻力與每步幅度；核對目標、UART ACK、實際機台回報及實際阻力方向。
5. 驗證負坡／平路／正坡的平滑變化，不超出設備設定範圍。
6. 量測停止按鈕、暫停、背景切換、控制者斷線與 30 秒租約逾時的實體停止效果；確認停止完成前重新 Start 的行為。
7. 測試第二個頁面競爭控制權、資料中斷、機台自行停止、心率拔除及重新配對。
8. 以實際 GPU 在 1080p 下記錄平均與低分位 FPS，驗證高畫質與自動降級；目前 60 FPS 是設計目標，尚未完成目標硬體效能量測。
9. 完成至少一趟五公里實機騎乘及長時間重複連線／騎乘測試。

結果填寫格式：日期、設備／韌體版本、設定值、操作、預期、實際、是否通過。真實心率、卡號及現場設備紀錄不提交 GitHub。
